# Exact-record recovery as part of the construction

The earlier catalog varied source recovery on/off, but retained one operation
when enabled: after nomination, every contiguous exact-record component inherits
its earliest member's nomination depth. Original nominees precede advanced
context, then stable chunk ID breaks ties. The earlier historical record probe
covered one known question and a different source-character budget; it did not
establish the construction under the shared serialized 72k serving contract.

This comparison retains the same opaque numeric component IDs. They represent
overlapping/touching source ranges of one exact record; no arbitrary radius,
body matching, gold, cost or additional semantic relation is introduced. Three
fixed parents (2,008-hit tag recruitment, 1,954-hit query-relative facet priority,
and 2,015-hit directed/tag combination) each receive five alternatives:

1. No component recovery.
2. Existing late minimum-depth recovery, unchanged parent control.
3. Maximum numeric evidence within each component before final nomination;
   late recovery is disabled. Facet/query streams remain separate until the
   parent combines them. Missing sibling evidence can inherit support.
4. The same evidence transport before the first graph operation, retaining
   ordinary late recovery. This tests whether recovered siblings can sponsor
   graph propagation, rather than only appear as context after ranking.
5. Component-contiguous context assembly after ordinary nomination/recovery.
   Components sort by earliest native member depth and head stable ID; members
   sort by native depth and stable ID. Candidate access remains unchanged.

These are hypotheses about how exact-record structure should act, not a claim
that inherited sibling evidence is semantically correct. In particular, early
transport can affect other graph neighbors. A small numeric witness verifies
that transporting before the graph can admit a neighbor that transporting only
after the graph cannot reach.

The shared 72,000 serialized-character prefix cut remains outside retrieval for
every alternative. It can split a contiguous component. There is no atomic-bundle
guarantee, cost-aware skip, or cheap-chunk packing. Body resolution and gold joins
occur only after the full order has been produced.

The isolated engine/helper and plan are additive; earlier sealed engines and
results remain intact. The one-case 16-program smoke independently verifies all
deliveries and exactly reproduces all three unchanged-parent orders, deliveries,
budgets and metrics. Five focused tests cover component transport, placement,
contiguous assembly, unsupported-member access and effective ordering at the
serving boundary.

Component assembly has different effective ordering keys from nomination depth.
`facet_record_assembly_inspection.ordering_audit` reports ID-sensitive component
groups crossing the serving cut, even when the cut lies inside one component
and neighboring chunks have different native depths. It also checks member-ID
ties. An old adjacent `final.depth` tie test cannot substitute for this audit.

The full 16-program original95 population completed: 1,520 independently verified
deliveries and all 285 unchanged-parent full-order/delivery/metric checks passed.
All five modes produce identical full orders and deliveries in each parent.
This is **inactive recovery**, not population evidence that the different
recovery constructions are equivalent. The numeric graph inventory proves why:
569 chunks belong to 157 multiple-chunk record components, and none of those
569 chunks has a nontrivial Product+Channel group. The winning intersection
paths exclude them. A pre-walk transport changes 2,060 evidence cells in the
first case, but those changes cannot survive that parent's graph access path.

An additive positive control therefore uses the already available Product
projection, which reaches all 4,808 chunks, including all 569 record fragments.
This route was chosen by graph overlap, not question content or gold failures.
The 2,008-hit tag parent and 1,954-hit query-priority parent each receive the
same five modes on that Product route, plus canonical reference: 11 programs.
The earlier 16-program evidence is preserved unchanged.

The one-case Product smoke verifies all 11 deliveries. Both late controls
reproduce the prior unchanged frontier engine exactly on the actual 30-group
Product graph. Modes produce different full orders in both contexts, so this
positive control genuinely exercises record assembly. Its full population is
`output/research/2026-09-24-record-product-programs/` and has completed 1,045
independently verified deliveries. All 190 late-control full orders, deliveries,
budgets and metrics reproduce a fresh execution through the prior unchanged
frontier engine on the Product graph. The complete accounting and parity record
is `record-product-audit.json` in that folder.

Unlike the winning Product+Channel contexts, these alternatives are active.
Disabling recovery changes all 95 complete orders and 30 delivered sequences in
each Product context, gaining 28 and 22 hits respectively (five case wins and
zero losses in each). Pre-nomination transport changes all 95 orders and 24/23
delivered sequences, while contiguous assembly changes all 95 orders and 27/26
delivered sequences; both retain the late control's gold hit counts. Pre-walk
transport changes 32/40 complete orders and 1/0 deliveries, gaining two hits in
the tag context and none in the query-priority context.

Therefore equal gold metrics do not mean these mechanisms were inactive. In
these reachable-fragment contexts, late recovery spends some of the shared
budget on context that displaces credited sources. The broader Product route
still underperforms the fixed 2,015-hit and 53.6217%-macro leaders; no final leader
changes. Source recovery's value beyond these measured source-ID outcomes is
not established by this experiment.

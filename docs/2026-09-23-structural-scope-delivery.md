# Structural scope formation through delivery

> **Status update, 2026-09-24:** this population is complete on all 95 cases
> and independently verified in `output/research/2026-09-23-scope-programs/`.
> Running/pending language below records the original protocol history. Current
> cross-family findings and limitations are in `2026-09-24-structural-outcome.md`
> and `2026-09-24-construction-coverage.md`.

The earlier graph-name capture tested scope composition but did not measure
delivery for those composed masks. This comparison closes that gap by feeding
the captured graph pointers into the existing numeric retrieval programs, then
applying the same 72,000-character cut and source-ID evaluation.

All 96 declared policies are evaluated for their mask sequences across the same
95 questions. They produce five distinct population-wide sequences, even though
each individual case has only three distinct outcomes. Identical sequences are
collapsed for this pinned population; every alias policy is retained in the plan.
This does not establish equivalence for future questions or other graph contents.

The five mask sequences and original frozen scope are crossed with joint/facet
recruitment, equal-depth/area-first/area-only admission, and scope before/after
traversal in two contexts: the earlier mean-query group-path leader and the
Employee-intersection sequential-path context. The canonical reference remains
the first row for independent verification. Total: 145 programs on 95 cases.

`tools/facet_scope_program_lab.py` contains the planner, graph-pointer adapter
and runnable entry point. It changes the case adapter's area only, leaving saved
numeric inputs intact. The scope function receives graph landings and eligible
IDs, with no corpus bodies or gold. A focused test checks that the original area
is preserved and the substituted area follows those pointers. The one-case smoke
passed independent verification for all 145 deliveries and input seals.

The full run is active in `output/research/2026-09-23-scope-programs/`. The page
tracks its status and supports its exact custom programs. Captures cover the
original 95 cases; attempting these custom scopes on the four recovered cases
returns an explicit coverage error instead of silently using the old scope.

Current limitations: name matching is the existing exact-name resolver, not an
LLM disambiguator or an OR parser. Captured landings contain Product and some
unrouted Company bindings; Employee/Channel name landing is not exercised by
these questions. No graph nodes or relationships are written. Live-DB versus
pinned-snapshot provenance remains as documented in the original capture.

Do not report a scope winner until the full population and independent checks
finish. The broader combined and ordering comparisons remain active alongside it.
